# オセロと将棋

スマホ・タブレット・パソコンのブラウザで遊べるオセロと将棋です。1台を交代で使う2人対戦と、コンピューター対戦を切り替えられます。

**アプリのURL:** https://daiki0807.github.io/futari-othello/

## できること

- 2人対戦／コンピューター対戦の切り替え
- コンピューターの難易度「弱い・普通・強い」

- 黒が先手の8×8盤面
- 置けるマスの目印
- 縦・横・斜めの8方向を自動反転
- 手番と石の枚数を表示
- 置けないときの自動パス、勝敗と引き分けの判定
- 確認してから最初から遊び直す

ゲームはページ内だけで動きます。対戦データをサーバーに送信しません。ページの再読み込みやタブを閉じると、対戦はリセットされます。

## コンピューター対戦

人が黒（先手）、コンピューターが白（後手）です。難易度の違いは次のとおりです。

- **弱い**: 置ける場所からランダムに選びます。
- **普通**: 角、角の近くの危険なマス、次に置ける場所などを評価して選びます。
- **強い**: 相手の応手も含めて最大5手先まで探索します。空きマスが10以下の終盤は、制限内で最後まで読みます。探索時間は通常最大350ms、ノード数にも上限があります。

思考はWeb Workerで行い、画面操作を妨げないようにしています。Workerが利用できない場合は探索量を減らして動作します。「強い」は完全読みや最善手を常に保証する設定ではありません。

モード・難易度を対戦途中で変更するときは、確認後に新しい対戦を始めます。思考中にリセット・設定変更の確認画面を開くと、古い思考を中止します。

## 将棋モード

画面上部の「将棋」を選んで切り替えます。通常の9×9盤で、1台を交代で使う2人対戦、または3段階のCPU対戦ができます。CPU対戦では人が先手（下側）、CPUが後手（上側）です。

- 駒を選ぶと合法な移動先を表示。取った駒は持ち駒になります。
- 成りの選択、行き場を失う駒の自動成り、持ち駒の打ちを実装。
- 王手・詰み、二歩、打ち歩詰め、王手放置、行き所のない駒を判定。
- 同一局面（盤面・持ち駒・手番）が4回なら千日手。連続王手の千日手は王手側の負け。
- 持ち時間・入玉宣言法はありません。両玉が敵陣に入り、王手がない場合は「持将棋を確認する」から合意して24点法で終了できます。CPU相手でも、この操作はプレイヤーによる合意の確認として扱います。
- 「弱い」は合法手からランダム、「普通」は駒の価値・取り返される危険・1手詰めを評価、「強い」は相手の応手を最大3手先まで先読みします。通常600ms／12000ノードの制限があり、競技用の将棋エンジンや棋力段級の保証ではありません。
- CPUはWeb Worker内で動作。利用できないときは探索量を抑えてフォールバックします。

「駒を動かして練習」では、8種類の駒の動き、取り方、成り、持ち駒を全11ステップで学びます。★のマスへ正しく指せたら次へ進み、完了後は弱いCPUとの対戦を始められます。

オセロ／将棋の切り替え中は、それぞれの対戦状態を保持し、非表示のCPU思考は停止します。将棋の練習中も本番の対局を保持します。ページの再読み込みでは初期化されます。

ルール確認元: [日本将棋連盟・将棋の基礎知識](https://www.shogi.or.jp/knowledge/shogi/)、[対局規則](https://www.shogi.or.jp/match/taikyoku_rules/)。チュートリアルの文章・練習局面は本アプリ用に作成しています。

## 開発

Node.js 22.13以上を使用します。

```sh
npm ci
npm run dev
```

## 検証

```sh
npm test
npx tsc --noEmit
```

ルールテストには、8方向の同時反転、不正手・盤面の端、自動パス、空きマスを残した終了、引き分け、独立した判定処理との100対戦分の比較が含まれます。AIの合法手、終盤12局面の最適結果、連続パス、手番の操作制限、リセット後の古い応答の無効化も検証します。

将棋では初期局面の3手先までの手数（30・900・25470）、全駒と成駒の動き、持ち駒・反則・詰み・千日手・チュートリアル・CPUの古い応答をテストしています。開発時には独立した `python-shogi` と720局面の合法手集合も比較して一致しました。検証用Pythonライブラリは製品の依存関係には含めていません。

## GitHub Pagesへの更新

GitHub Pagesの配信元は `main` ブランチの `/docs` です。`docs/` は生成物専用です。

```sh
npm run build:pages
git add .
git commit -m "Update Othello"
git push origin main
```

GitHub側がプッシュされた `docs/` を公開します。`docs/.nojekyll` により、`_next` 以下のファイルも配信されます。ソースだけ変更した場合も、必ず `npm run build:pages` を実行してからコミットしてください。

1ページ構成の静的書き出しを使い、CSS・JavaScriptの参照先は `/futari-othello/` に合わせています。リポジトリ名を変える場合は `next.config.ts` と `app/layout.tsx` の配信パスも変更してください。

既存のSites向け設定も保持しています。`npm run build` はSites向け、`npm run build:pages` はGitHub Pages向けです。
